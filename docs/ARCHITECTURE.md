# 架构与边界说明 — 开奖站 + Go CMS + Bot

## 1. 为什么在 Node 旁边加个 Go 服务，而不是全重写？

老的 Node 业务已经在线上稳跑了，全重写风险大也没必要。内容管理、图片重编码、SEO 静态页渲染和运行监控刚好跟资金账本没关系，拆成一个独立的 Go 二进制放到 `127.0.0.1:8092`，Nginx 把 `/api/cms/`、`/article/`、`/sitemap.xml` 切过去就行。万一 CMS 挂了，也不影响主站下单和结算。

## 2. 几个踩过坑才补上的设计

- **写文件必须 `fsync + rename`**：CMS 的 `cms.json`、`media.json`、`taxonomy.json`、`drafts.json` 和性能历史文件都用原子替换写盘，避免断电或进程被杀时文件写一半变坏。
- **图片解码防 OOM**：先读图片头检查宽高（不超过 1200 万像素、单边不超过 12000px），单实例一次只解码一张图（并发直接返回 `429 Retry-After: 2`），缩放至长边 <= 1920px 后重编码。
- **巡检绝不发 HTTP 请求**：检查文章里的站内图和链接是否失效时，只把同源 URL 映射到本地只读目录核对，彻底杜绝 SSRF 和目录穿越。
- **外部备份状态只读不执行**：CMS 可以展示备份状态页，但本身绝不跑 shell、不连备份机、不读密钥，只读运维脚本写出来的受限 JSON 状态文件。
